Question: How can Service Control Policies (SCPs) be used effectively to enforce security and compliance across an AWS Organization, and what are their limitations?

Plausible Answer:

SCPs are powerful for setting broad preventative guardrails across accounts. For example, we can use SCPs to restrict regions, disable certain high-risk services (e.g., those not yet approved or understood), or enforce the use of encryption. They act as a filter on IAM permissions, meaning even an admin in a member account cannot perform actions denied by an SCP. Limitations include: SCPs don't grant permissions, only restrict them; they don't apply to the management account; they can be complex to manage and test; and they don't support conditional logic as granularly as IAM policies. They are best used for coarse-grained controls, complemented by IAM policies for fine-grained access.

Ranking Guidelines:

Question Format: Compare and Contrast - Service Nuances

Challenge:
For managing application configurations and secrets in AWS, two commonly mentioned services are AWS Systems Manager Parameter Store and AWS Secrets Manager.

Compare and contrast these two services. What are their key similarities, differences, and in what specific scenarios would you choose one over the other for a banking application?

Plausible Answer:
Similarities:

- Both provide a centralized, secure store for configuration data and secrets.
- Both integrate with IAM for access control.
- Both can store parameters hierarchically.
- Both support encryption (Parameter Store via KMS, Secrets Manager has its own envelope encryption with KMS).

Differences:

- **Primary Use Case:** Parameter Store is broadly for configuration data (plain text or encrypted) and secrets. Secrets Manager is purpose-built for secrets, with advanced features like automatic secret rotation.
- **Secret Rotation:** Secrets Manager offers built-in, automated rotation capabilities for services like RDS, DocumentDB, and Redshift, and can be extended with Lambda for other secret types. Parameter Store does not have built-in automatic rotation.
- **Cost:** Parameter Store standard parameters are free; advanced parameters and higher API throughput have a cost. Secrets Manager charges per secret per month and per API call. Secrets Manager is generally more expensive.
- **Cross-Account Access:** Secrets Manager has more straightforward resource-based policies for sharing secrets across accounts.

When to Choose Which for a Banking Application:

- **AWS Secrets Manager:** Choose for secrets that require regular, automated rotation (e.g., database credentials, API keys for third-party services). Its enhanced security features and rotation capabilities are critical for sensitive credentials in a bank. The cost is justified by the reduced risk and operational burden of manual rotation.
- **AWS Systems Manager Parameter Store:** Choose for general application configuration data (e.g., feature flags, service endpoints, non-sensitive settings). It can also be used for secrets that don't require automatic rotation or where cost is a major driver and manual/less frequent rotation is acceptable (though for critical secrets in a bank, Secrets Manager is usually preferred). Use the SecureString type for sensitive parameters.

Ranking Guidelines:

High: Clearly articulates several key similarities and differences, especially highlighting automatic rotation and cost. Provides clear, context-aware (banking) scenarios for choosing each service, emphasizing security and compliance drivers for Secrets Manager.

Medium: Identifies some differences (e.g., rotation) but may be less comprehensive. Scenarios for choosing one over the other might be less distinct or not strongly tied to banking requirements.

Low: Shows confusion between the services, identifies few or incorrect differences, or cannot provide clear guidance on when to use each.
